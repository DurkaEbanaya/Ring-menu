# Диагностика и исходники

Актуальное описание запуска и ограничений: [основной README](../README.md).

## Компоненты

| Файлы | Назначение |
|---|---|
| `RingLab.cs` | Общая геометрия/отрисовка и изолированный сенсорный стенд. Без `EXPLORER_RING` не подключается к Explorer. |
| `ExplorerRingOverlay.cs` | Неактивирующее кольцо и подложка для отмены смещённого меню. |
| `ExplorerRing.cs` | Контроллер временного перехвата; отслеживает подходящее активное окно, отключается через 3 минуты. |
| `ExplorerRename.cs` | UI Automation hit test + Shell identity checks; штатный label editor через `SelectItem(SVSI_EDIT)`. |
| `ExplorerBridge.c`, `ExplorerBridge.h`, `BridgePolicy.h` | Экспериментальный native перехват touch, shared-memory transport, политика жеста. |
| `ExplorerObserver.c`, `ExplorerProbe.cs` | Отдельный пассивный thread-specific наблюдатель. DLL наблюдателя не меняет сообщения. |
| `TouchProbe.cs` | Ранний пассивный наблюдатель promoted mouse input и тестовая touch-панель. |

## Сборка

- `bash build-observer.sh`: SDK-free Windows x64 native DLL + локальные C-тесты политики.
- `build-ExplorerRing.ps1`: актуальный `ExplorerRing-v05.exe`; положить рядом `ExplorerBridge-v05.dll`.
- `build-ExplorerProbe.ps1`: пассивный Explorer Probe.
- `build.ps1`: Touch Probe и автономный Ring Lab.

Версионные выходные DLL 0.1–0.4 оставлены для совместимости имён при разработке, но **пересобираются из текущего кода**, а не являются историческими релизами. Для текущей версии используйте исключительно пару `-v05`. Не заменяйте DLL запущенной программы.

## Автотесты

```powershell
.\ExplorerRing-v05.exe --self-test
Get-Content .\explorer-bridge-self-test.log
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-ExplorerRing.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-RingLab.ps1
```

`--self-test` создаёт только невидимое собственное окно: проверяет DLL/ABI/GET+CALL hooks/queue/unhook, сохранность ответа окна, разрешение пересозданного view, отказ опасных целей, чистые проверки сопоставления/неоднозначности имён. Не подключается к Explorer, не вызывает переименование и не подтверждает desktop COM/UIA интеграцию.

`Test-ExplorerRing.ps1`: 49 позиций, 294 попадания в секторы, границы экрана, зона пальца, исходное отпускание в FIXED и отмена снаружи. Не заменяет ручной тест touchscreen.

## Проверки вручную для 0.5

- Последовательно переименовать несколько ненужных файлов в разных папках, разных окнах и на рабочем столе.
- Удерживать **невыделенный** файл при выделенном другом: действие относится к файлу под пальцем, не к старому выделению.
- Проверить DRAG и FIXED; у FIXED исходное отпускание ничего не выполняет.
- Удержать пустое место; сделать множественное выделение; изменить содержимое/папку перед выбором: безопасный отказ.
- Проверить обычный тап, быстрый drag, физическую ПКМ и Shift+F10 при закрытом кольце.
- Во время кольца переключить приложение: отмена. Не проверять во время важных копирований.
- После успешного вызова кольца переместить ненужный значок обычным быстрым drag по рабочему столу, затем снова удержать его. Повторить несколько раз и проверить переименование; кольцо не должно переставать вызываться. Повторить в папке.

### Исправление desktop drag (0.4)

При обычном перемещении значка Windows может закончить контакт через `WM_POINTERLEAVE` с `INCONTACT=0`, без `WM_POINTERUP` в наблюдаемой очереди. Ранее незахваченный кандидат сохранял старый ID и воспринимал все следующие DOWN как вторые пальцы. Политика теперь сбрасывает такой завершённый контакт; новый primary DOWN другого ID дополнительно восстанавливает только незахваченный кандидат. Захваченный контакт новым DOWN не заменяется. `LEAVE` с `INCONTACT=1` и чужим ID не завершает жест. При завершении захваченного контакта без настоящего UP контроллер получает отмену, не выбор сектора.

`Test-BridgePolicy.c` воспроизводит последовательность desktop drag → terminal LEAVE без UP → новое удержание; проверяет порог, сохранность активного/чужого контакта и запасное восстановление без terminal message. Это регрессия логики, не доказательство исправления на физическом устройстве.

### Потеря события и ранняя остановка (0.5)

Повторный тест 0.4 показал `STOP_REQUEST Queue overflow` примерно через 37 секунд после ARM и `dropped=1`, а не истечение 180 секунд. Старый общий счётчик учитывал и заполнение очереди, и неблокирующий отказ при конкуренции за lock, включая чисто диагностические записи: журнал не позволяет отличить конкретный вид/источник потери. Поэтому это не доказательство физического заполнения всех 512 слотов.

В 0.5 `EventQueue.h` оставляет последние 64 слота только для управления; соседние MOVE одного ID/окна объединяются с сохранением последней позиции. MOVE ограничены одним за 16 мс, кроме cancelled; UP/начало/отмена не ограничены. Потери диагностики считаются отдельно и не останавливают сессию. Потеря любого события управления всё ещё приводит к отмене и безопасной остановке. Непрерывные движения больше не форматируются в журнал, буфер журнала сбрасывается раз за UI tick вместо каждой строки. Причина остановки и разные счётчики показаны в окне.

`Test-EventQueue.c`: 100000 объединений MOVE, резервирование слотов, сохранение UP/отмены, запрет объединения разных ID/окон, исчерпание важных слотов и wrap индексов. Сборочный скрипт выполняет этот тест и тест политики. Стабильность трёхминутной физической сессии требует ручной проверки.

В журнале `TARGET_CAPTURED` означает получение проверяемой цели, `TARGET_REFUSED`/`RENAME_REFUSED` — отказ, `RENAME_EDIT_REQUESTED` — только возврат из Shell-запроса, **не доказательство успешного переименования**. Файловые пути/имена и текст исключений не логируются.

## Исследовательские выводы

Стационарное удержание на исследованном Windows 10 даёт promoted RMB только после отпускания. Ранний `WM_POINTERDOWN/UPDATE` доступен внутри GUI-потока Explorer; поздний `WM_CONTEXTMENU` может не иметь признака touch. Поэтому эксперимент коррелирует исходный pointer lifecycle, не угадывает источник по последнему popup menu.

`GetPointerInfo` нельзя надёжно использовать для чужого окна из внешнего процесса. Здесь он вызывается native hook в целевом потоке. Microsoft предупреждает о неопределённом поведении при частичном потреблении pointer sequence; используемая синтетическая очистка остаётся экспериментом, не гарантированным API отмены жеста.

Filee — полезный пример отдельного радиального окна, но не подтверждение touchscreen interception. Nilesoft Shell перехватывает обычные popup menu и рисует стандартную menu-loop структуру; радиальный градиент не означает радиальную раскладку. Ни Filee, ни Nilesoft в систему не устанавливаются.

Локальные исследовательские заметки, сырые логи и готовые бинарники исключены из Git. При публикации диагностических журналов отдельно проверяйте их содержимое.
